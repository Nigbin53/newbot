# Путь: публикация через GitHub

Код лежит в репозитории GitHub. Каждый `git push` в ветку `main` сам запускает публикацию (GitHub Actions):

1. тесты;
2. база данных и сервер в Supabase;
3. сайт приложения на GitHub Pages;
4. кнопка **Открыть Путь** в меню бота.

Токены хранятся в секретах репозитория GitHub — не в коде и не в чате.

## 1. Бот: BotFather

1. Открой [@BotFather](https://t.me/BotFather), отправь `/newbot`.
2. Укажи название и имя бота с окончанием `bot`.
3. Сохрани токен — это `BOT_TOKEN`. Никому его не отправляй.

## 2. Supabase: проект и токен

1. В [Supabase Dashboard](https://supabase.com/dashboard) создай проект **Путь**.
2. Пароль базы данных сохрани — это `SUPABASE_DB_PASSWORD`.
3. **Project ID / Reference ID** (20 латинских букв из адреса после `/project/`) — это `SUPABASE_PROJECT_REF`.
4. В [Access Tokens](https://supabase.com/dashboard/account/tokens) создай токен для этого проекта — это `SUPABASE_ACCESS_TOKEN`:

| Разрешение | Значение |
| --- | --- |
| Project Settings | Read |
| API Keys | Read |
| API Key Secrets | Read |
| Edge Functions | Read-write |
| Edge Function Secrets | Read-write |

## 3. GitHub: репозиторий и секреты (один раз, в браузере)

1. [Создай репозиторий](https://github.com/new): имя `kinpass`, **Public**, без README и .gitignore.
2. **Settings → Pages → Source:** выбери **GitHub Actions**.
3. **Settings → Secrets and variables → Actions → New repository secret** — добавь четыре секрета:

| Имя | Значение |
| --- | --- |
| `BOT_TOKEN` | токен от BotFather |
| `SUPABASE_ACCESS_TOKEN` | токен доступа Supabase |
| `SUPABASE_DB_PASSWORD` | пароль базы данных |
| `SUPABASE_PROJECT_REF` | ID проекта Supabase |

## 4. Первая отправка (один раз)

Папка уже является git-репозиторием с первым коммитом. Привяжи её к GitHub и отправь:

```sh
cd ~/Desktop/passmd && git remote add origin https://github.com/Nigbin53/kinpass.git && git push -u origin main
```

Через 3–5 минут приложение будет по адресу `https://nigbin53.github.io/kinpass/mini.html`, а в боте появится кнопка **Открыть Путь**. Ход публикации — вкладка **Actions** в репозитории.

## 5. Обновления — одна строка

Claude исправляет код и сам делает коммит. Тебе остаётся:

```sh
cd ~/Desktop/passmd && git push
```

Тесты, база, сервер, сайт и кнопка бота обновятся сами. Если поменялся токен или пароль — обнови секрет в Settings → Secrets и нажми **Actions → Публикация Kinpass → Run workflow**.

## ИИ-помощник (необязательно)

Ищет адрес, телефон, часы работы и приёма учреждений (Google Maps и поиск) и отвечает на вопросы в чате бота обычным текстом.

1. Открой [Google AI Studio → API keys](https://aistudio.google.com/apikey) и нажми **Create API key**.
2. Добавь ключ в GitHub: **Settings → Secrets and variables → Actions → New repository secret**, имя `GEMINI_API_KEY`.
3. Перезапусти публикацию: **Actions → Публикация Kinpass → Run workflow** (или сделай любой push).

Модель по умолчанию — `gemini-3.8-flash`; другую можно задать секретом `GEMINI_MODEL`. На одного пользователя — до 40 запросов к ИИ в день. Без ключа приложение работает как обычно, кнопка «Заполнить с ИИ» покажет, что помощник не подключён.

## 6. Открыть в Telegram

Открой своего бота и нажми **Start** — бот ответит приветствием с кнопкой **Открыть Путь**. Та же кнопка всегда есть слева от строки сообщения. При первом входе дело пустое. Добавь документ, закрой приложение и открой снова — запись загрузится из облака.

Приложение работает только из кнопки бота: сервер проверяет подпись Telegram. Обычная ссылка в Safari вход не даёт.

## Если публикация остановилась

Открой **Actions** → последний запуск → красный шаг.

| Шаг | Что сделать |
| --- | --- |
| Проверить секреты | Добавь недостающий секрет в Settings → Secrets and variables → Actions. |
| Тесты | Код сломан — исправь и снова сделай push. |
| Supabase — база данных и сервер | 401/403 — проверь `SUPABASE_ACCESS_TOKEN` и его права. Ошибка пароля — `SUPABASE_DB_PASSWORD`. |
| Проверить сервер | Supabase → Edge Functions → kinpass-api → Logs. |
| configure-pages / Опубликовать | Settings → Pages → Source должен быть **GitHub Actions**. |
| Кнопка бота | Проверь `BOT_TOKEN`. |

## Что важно знать

- Репозиторий публичный — бесплатный GitHub Pages работает только так. Видно только код; документы, фото и токены в него не попадают.
- Дело привязано к Telegram ID. «Я», «Мама», «Дед» — владельцы документов одного общего комплекта для одного паспорта.
- Всё дело (документы, поездки, заказы, дата подачи) хранится в Supabase и открывается с любого устройства. Копии файлов, добавленные в карточке документа, хранятся только на том устройстве, где их добавили.
- При первом открытии «Путь» переносит прежние документы и учреждения Kinpass: город и учреждение становятся поездкой, «в работе» — заказом, «получен» — полученным документом. Даты не придумываются: поездка без даты стоит в конце плана.
- Даты, требования и список документов вводишь ты сам: приложение не знает официальных требований.
