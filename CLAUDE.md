# Путь — контекст для работы

Общаться с пользователем по-русски. Telegram mini app + Supabase + GitHub Pages. Обновление — `git push` в main (GitHub Actions публикует всё сам).

## Продукт
- ОДИН паспорт; документы принадлежат трём поколениям: «Я» (self), «Мама» (mom), «Дед» (grandpa). Общие заявка, финальный комплект, дата и город подачи.
- Главная потребность: «поехать ТУДА и заказать ТО И ТО». «План» — нумерованные поездки по городам и датам, под городом — что заказать.
- «Заказал» и «Получил» — разные состояния (`state.orders` vs `doc.received`). Готовность растёт только от полученных действительных документов.
- В «Поездках» фильтр по городам, в «Обзоре»/«Документах» — по владельцу; фильтры независимы.
- Даты не придумывать: поездка и подача могут быть без даты («дата не выбрана»), такие поездки стоят в конце плана.
- Светлый интерфейс (референсы Things и Wanderlog). Без обязательного ИИ-чата; ИИ только как кнопка «Найти адрес и контакт» в редакторе встречи и ответы бота в чате.

## Код
- `web/` — обычные HTML/CSS/JS без сборки. Порядок CSS в `mini.html` важен: поздние файлы переопределяют ранние; `telegram.css` — последний (полноэкранный режим вместо рамки телефона).
- Состояние «Пути» (version 3): documents, visits, passportCase, orders, checks, files, places. Сохраняется на сервер (`save-put`, ревизия как защита от одновременных правок). Копии файлов — IndexedDB только на устройстве.
- Сервер: `supabase/functions/kinpass-api` (вход по initData, load/save-put, lookup через Gemini), `kinpass-bot` (/start и ответы на вопросы), `_shared/put.mjs` (перенос из Kinpass, проверка, сводка для бота).
- Тесты: `npm test` (нужен `npm ci`). Перед заявлением о готовности интерфейса — смотреть экраны в размере iPhone.
- Данные пользователя не сбрасывать; демо-данные прототипа в приложение не возвращать.
